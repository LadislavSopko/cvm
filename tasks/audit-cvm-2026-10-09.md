## 0. Executive summary (IT)

Il progetto è **piccolo e sano nelle fondamenta TypeScript** (strict, ES2022, nessun `var`, nessun `@ts-ignore`, 1 237 test), ma ha tre problemi strutturali:

1. **Correttezza silenziosa del compilatore** — il compilatore accetta codice sintatticamente sbagliato e sceglie le istruzioni solo dal *nome* del metodo, non dal tipo: `arr.includes`, `arr.indexOf`, `arr.toString` sono rotti, `x === undefined` è sempre `false`. Dimostrati con 11 test.
2. **Duplicazione e codice morto nella VM** — 91 oggetti errore scritti a mano, doppi controlli di stack, 15 opcode su 93 con handler mai emessi dal compilatore (incluso un `ARRAY_SLICE` che ho duplicato io nella feature 08 — autocorrezione sotto).
3. **Toolchain ferma 1-2 major indietro** su tutto (TS, Nx, Vitest, Vite, Zod, SDK MCP), Node 18 fuori supporto, nessuna CI, nessun lint.

La semplificazione con ROI più alto: **tabella dichiarativa per i metodi nel compilatore** (risolve DRY *e* i bug di tipo), **helper `runtimeError()` nella VM**, **rimozione del codice morto**, **CI minima**.

## 5. Overengineering

Overall low: no microservices, no infra beyond one nginx for docs, a monorepo of 7 small packages. The visitor-per-node compiler and handler-per-opcode VM are proportionate. Overengineering is *local*: three-layer stack defense, factory+adapter for one backend, unused opcode surface (16%), token ceremony. Package split (`types` ↔ `parser` re-export of `OpCode`, `parser/src/lib/bytecode.ts` is a 4-line compatibility re-export) adds indirection without consumers needing it.

## 8. Self-correction

- **Feature 08 block 03 (mine):** I added array support inside `STRING_SLICE` without noticing that `ARRAY_SLICE` already existed (`arrays.ts:409`) but was never emitted. Behaviour is correct (tests green) but it is a DRY violation I introduced; tracked in §3.
- **Earlier in this session** I claimed "submitTask does not execute the VM"; code proved the opposite (`vm-manager.ts:215`). Fixed in 2.1.0; the stale "READ-ONLY" comment at `vm-manager.ts:112` is the trap that caused it (§2).

## 9. Recommendations (ROI order)

**Quick wins (< 1 day)**
1. Syntax diagnostics in `compile()` + delete `parser.ts` pass (B1-B3).
2. Fix B10 (accept `## Step N:` titles) and B11 (real nonce or `confirm: true`).
3. Delete dead code: CALL/GET/SET/JUMP_IF/DUP2/*_PROP handlers + tests, `getCurrentContext`, `iterVariable`, commented port config, `static/`, `graph.html`, `counter.ts`, `benchmark/`, `test/programs/archive/`.
4. One trace log per instruction, guarded.
5. Minimal CI: build + typecheck (no cache) + test + e2e on push.

**Medium (1-2 weeks)**
6. Table-driven method dispatch with runtime receiver typing (B4-B6, DRY); reuse ARRAY_SLICE/ARRAY_INDEX_OF.
7. `runtimeError()` helper; drop `safePop` in favour of `stackIn`.
8. `undefined` comparison semantics (B7-B8).
9. Single config object passed down; enforce or delete limits (B9).
10. SDK MCP 1.32 + `registerTool` + shared tool error wrapper.

**Strategic (1-3 months)**
11. Toolchain majors (TS, Nx, Vitest, Vite, zod 4, pino 10) and Node 20/22.
12. Lint (eslint flat config or biome) with `noPropertyAccessFromIndexSignature` everywhere.
